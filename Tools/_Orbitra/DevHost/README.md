# Локальное лобби Orbitra

Соберите `Content.Server`, затем запускайте dev-клиент через
`dotnet run --project Content.Client` или `bin/Content.Client/Content.Client.exe`.
В главном меню доступна кнопка «Подключиться напрямую + лобби».

Dev-сборка заменяет только apphost клиента небольшим `Orbitra.DevHost`.
Он запускает исходный `Content.Client.dll`, сохраняя песочницу Robust,
и принимает единственную операцию — запуск локального сервера.
Изолированный канал запроса/ответа в userdata создаётся на каждый запуск.
Прямой запуск DLL и release-клиент работают без этой кнопки.

Сервер слушает только `127.0.0.1:1214`, не публикуется в хабе и использует
`bin/OrbitraDevLobbyData` и `bin/orbitra_dev_lobby.toml`. При отсутствии новых путей используются существующие `LimeDevLobbyData` и `lime_dev_lobby.toml`, чтобы сохранить базу и настройки. Обычный dev-сервер на 1212
не изменяется. Лобби ожидает 10 минут; карта после старта — Dev, режим — песочница.
Уже работающий сервер не перезапускается и не останавливается этим клиентом.
Созданный хостом сервер завершается при закрытии дочернего клиента.
Для подготовки сервера нужна установленная .NET SDK; для уже подготовленной сборки достаточно соответствующего runtime.
Если сервер отсутствует или его общие сборки отличаются от клиента, dev-хост собирает совместимый сервер в `bin/Orbitra.DevServer`. Обычный `bin/Content.Server` не перезаписывается. Журналы сборки: `build.log` и `build-errors.log` в изолированном каталоге; после изменения исходников сначала пересоберите клиент.

Проверки: `OrbitraDevLobbyTest` в `Content.Tests`; явный тест
`RealDevServerStartsWithLobby` запускает настоящий сервер на 1214.
