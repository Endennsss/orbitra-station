# Default Orbitra UI Theme Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans inline, with a fresh final review.

**Goal:** Обычные окна, в том числе ванильные, автоматически получают базовый интерфейс Orbitra без вызовов в каждом конструкторе.

**Architecture:** UIController наблюдает WindowRoot. OrbitraWindowTheme подключает общую рамку и жизненный цикл для FancyWindow/DefaultWindow, OrbitraControlTheme оформляет дерево и новые узлы событийно. OrbitraEditorStyles остаётся модулем специализированных раскладок поверх общего оформления.

**Tech Stack:** C#, Robust UIController, BaseWindow, CommonSheetlet, NUnit integration tests.

**Spec:** Пользователь выбрал применение ко всем обычным окнам, с явным исключением для специальных интерфейсов. Сохраняются действующие цвета и вид Orbitra; больше не нужны Attach/Apply в новых окнах.

## Global Constraints

- Код `_Orbitra`, без изменений RobustToolbox, без покадрового обхода UI.
- Сохранять явные размеры, прокрутку, поведение кнопок и специальные раскладки.
- Повторное подключение и открытие не создаёт дубликаты заголовков, закрытия, событий.
- Нативные Close/Dispose немедленные; пользовательское закрытие сохраняет анимацию.
- Исключение: StyleClass OrbitraNativePresentation, заданный до первого открытия.
- Тяжёлые проверки последовательны, ограничение heap .NET, остановить процессы.

## Review Focus

## Ruling

Базовая тема не управляет геометрией вообще: штатные API могут измерять окно до Open, поэтому автоматическое изменение MaxSize/SetSize создаёт несовместимые ограничения. Подгонка и перестройка остаются явным декларативным профилем OrbitraEditorLayout. Это сохраняет существующие редакторы и не требует стилевых вызовов в новом обычном окне.
