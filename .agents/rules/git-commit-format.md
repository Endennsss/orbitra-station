# Lime Station: формат сообщений коммитов

## Завершение работы

- Перед завершением задачи, в которой были изменены файлы репозитория, обязательно
  спроси пользователя, нужно ли создать коммит и отправить его через push.
- Не создавай коммит и не выполняй push до получения явного согласия пользователя.
- Не повторяй вопрос, если пользователь уже попросил выполнить коммит и push в
  текущей задаче либо явно отказался от них.
- Если работа затрагивает несколько репозиториев или submodule, перечисли их в
  вопросе отдельно.
- Для задач без изменений репозитория этот вопрос не требуется.
- Создавай pull request только по отдельному прямому запросу пользователя.

При создании коммитов в этом репозитории обязательно используй формат:

```text
<type>: <краткое описание изменения>
```

Префикс пиши строчными английскими буквами, после двоеточия ставь один пробел. Выбирай один префикс по основной цели изменения:

- `add:` — новая функция, контент, ресурс или правило.
- `fix:` — исправление ошибки.
- `tweak:` — небольшая настройка поведения, баланса или внешнего вида.
- `remove:` — удаление функции, контента или устаревших файлов.
- `refactor:` — изменение структуры кода без изменения поведения.
- `docs:` — изменение документации.
- `test:` — добавление или изменение тестов.
- `build:` — изменение сборки, зависимостей или упаковки.
- `ci:` — изменение автоматических проверок и GitHub Actions.
- `chore:` — техническое обслуживание, не подходящее под остальные типы.
- `upstream:` — синхронизация с upstream.
- `revert:` — отмена предыдущего изменения.

Описание должно конкретно объяснять результат изменения и быть написано только на русском языке. Не используй несколько префиксов в одном заголовке, общие сообщения вроде `fix: fixes` и точку в конце заголовка. По возможности укладывай заголовок в 72 символа; дополнительные пояснения помещай в тело коммита после пустой строки.

Примеры:

```text
add: добавить правило формата коммитов
fix: исправить русские местоимения в сообщениях
tweak: обновить шрифт чата и убрать обводку
upstream: синхронизировать изменения Space Station 14
```

Правило применяется к новым сообщениям коммитов, которые создаёт ИИ. Сохраняй существующие сообщения импортированных upstream-коммитов и не переписывай историю только ради формата. При автоматическом merge используй `upstream:` для синхронизации с upstream либо `chore:` для остальных объединений; при revert используй `revert:`.
